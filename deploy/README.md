# Ubuntu service deployment

These scripts preserve the standalone server, persistent data/auth paths, protected streaming proxy, and remote ChatGPT loopback sign-in helper used for this deployment. They target Ubuntu 24.04 amd64 with systemd. Run them as root on the application host. They do not create cloud infrastructure or configure a model.

## Initial setup

Point your hostname at an HTTPS load balancer with a valid certificate. Forward to host port 8080; restrict inbound 8080 to that load balancer. Use `/healthz` as the unauthenticated health check. The proxy assumes TLS terminates upstream and sets `X-Forwarded-Proto: https`. Do not expose ports 3000 or 3001; both bind loopback. The service permits only the configured hostname.

Copy this directory to the host. Set `DOMAIN` to your hostname, `LH_REPOSITORY` to the fork's clone URL, and `LH_BUILD_COMMIT` to the full 40-character commit you want installed:

```sh
sudo env DOMAIN=learn.example.com \
  LH_REPOSITORY=https://github.com/YOUR_NAME/learnharness.git \
  LH_BUILD_COMMIT=YOUR_FULL_COMMIT_SHA bash deploy/install-app.sh
```

The installer downloads Node (default 26.13.1, override with `NODE_VERSION`), verifies its SHA256, installs native Chrome, builds plugins and the standalone server, runs the standalone smoke check, and starts the service. Releases live under `/opt/learnharness/releases/COMMIT`; `/opt/learnharness/current` selects the active release. The systemd unit is generated by `install-app.sh` with the chosen Node path, domain, commit and package version.

Install Caddy (`apt-get install caddy`) and generate a fresh password hash interactively with `caddy hash-password`. Create `/etc/learnharness/proxy.env` as root, mode 0600, using the following shape. Replace the placeholder hash with the generated hash. Keep the hash in single quotes so its dollar signs survive shell parsing; this file is loaded by the installer shell. Use the `learning` username to match the Settings password-change helper.

```sh
LH_BASIC_USER='learning'
LH_BASIC_PASSWORD_HASH='REPLACE_WITH_GENERATED_BCRYPT_HASH'
```

Then run:

```sh
sudo env DOMAIN=learn.example.com bash deploy/install-proxy.sh
```

This installs `Caddyfile`, `oauth-helper.py`, the helper unit, and the initial root-owned `/etc/caddy/learnharness-users.caddy` credential include. `/etc/learnharness/oauth.env` contains `LH_PUBLIC_ORIGIN=https://YOUR_DOMAIN`; the helper requires a bare HTTPS origin without a path or port. Reinstalling the proxy preserves an existing credential include, including password changes made through Settings. The proxy authenticates both the app and `/connect-chatgpt`, strips the proxy password before forwarding, and disables buffering for event streams. `/healthz` is intentionally public and reveals only `ok`.

## Persistent configuration and sign-in

The application runs as the unprivileged `learnharness` user. Data and settings remain in `/var/lib/learnharness/data`; provider authentication remains in `/var/lib/learnharness/auth/auth.json`. Optional application environment variables go in `/etc/learnharness/runtime.env` (root-owned, mode 0600); restart `learnharness` after editing. Do not override the loopback binding or allowed hostname casually. `LH_BUILD_COMMIT` and `LH_VERSION` are set from the installed source and package version for the release tracker.

Configure models in the application's settings after deployment. For ChatGPT sign-in from a remote browser, visit `/connect-chatgpt`, open the authorization link, then paste the complete final `http://127.0.0.1:PORT/auth/callback?...` address into the helper. Keep that callback private. The helper accepts only the pending flow's loopback destination and matching state, expires flows after three minutes, rejects cross-origin submissions, and does not log credentials or callback URLs. A failed start can be cleared with its reset button.

## Updates and rollback

Push application customizations to the repository first. Rerun `install-app.sh` with the new full commit SHA, the same repository and domain; it builds an immutable release before switching `current`. Persistent settings and auth are kept outside releases. This is a manual update process: no update timer or backup task is installed. If an activation fails, select the previous release with an atomic `current` symlink replacement, update the generated systemd unit's `LH_BUILD_COMMIT` and `LH_VERSION` to match it, run `systemctl daemon-reload`, and restart `learnharness`. Preserve the previous release until the new deployment is verified.

Check `systemctl status learnharness learnharness-oauth caddy` and the service journals locally. Verify HTTPS unauthenticated root/API requests return 401, authenticated UI and API requests succeed, settings persist across restart, cross-origin writes return 403, and `/api/events` returns `text/event-stream` through the proxy. Never publish runtime env files, auth files, passwords, browser profiles, or logs.

The hosted Settings → General panel can change the `learning` sign-in password.
Run `bash deploy/install-password-helper.sh` as root after proxy installation,
then restart the app as part of the release. The app remains unprivileged;
a root-owned helper accepts only bounded password-change requests over a Unix
socket restricted to the application group. It verifies the current bcrypt
password, enforces matching new passwords of 12 characters minimum and 72 bytes
maximum, and allows five attempts per 15 minutes. It atomically updates only the
`learning` entry in `/etc/caddy/learnharness-users.caddy`, validates and reloads
Caddy, and rolls back on failure. Passwords are never written to logs or disk.
The browser's cached Basic Auth credentials become stale after a change; sign
in again with the new password. Keep the helper scripts root-owned and do not
grant the application sudo access. All public application routes must remain
behind the Caddy Basic Auth block; only `/healthz` is public.
